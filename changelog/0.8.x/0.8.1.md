# 0.8.1 — 2026-11-26

## Added

- **Input aliases** — `dataset_id` for `dataset` on every tool that takes one; `keyword` for `query` on `census_search_variables` and `census_list_predicate_values`; `place_name`, `place`, and `query` for `name` and `geography_level` for `geography_type` on `census_resolve_geography`; and the resolver's `state_fips`, `fips_summary`, and `geography_type` (plus sibling spellings `within`, `within_county`, `parent_fips`, `county_fips`) on the two data tools. An alias beside its target, or two aliases of one target, is rejected; `tools/list` is unchanged. ([#99](https://github.com/cyanheads/census-mcp-server/issues/99))

## Changed

- **Over-cap `limit`** on `census_query_data` and `census_compare_geographies` (500), `census_search_variables` (now 3,000, was 100), and `census_list_predicate_values` (now 10,000, was 500) is served at the cap with a sentence in `notice`, not rejected with -32602. `tools/list` advertises no `maximum`; `CENSUS_CLAMP_LIMITS=false` restores the rejection, and a malformed value (`CENSUS_CLAMP_LIMITS=maybe`) stops startup. ([#95](https://github.com/cyanheads/census-mcp-server/issues/95))
- **Counts in `notice` prose** on `census_search_variables`, `census_compare_geographies`, and `census_list_predicate_values` are grouped (`19,423`); offsets in `offset: N` recipes stay bare, and a one-code list reads `1 code`.

## Fixed

- **`CENSUS_DEFAULT_YEAR` is removed.** It never changed the default vintage, and a malformed value failed six tools at call time; a set value is now ignored. ([#96](https://github.com/cyanheads/census-mcp-server/issues/96))
- **`CENSUS_VARIABLE_CACHE_TTL_HOURS`** — a malformed value now stops startup with the configuration banner instead of failing six tools at call time.
- **dec/pl 2000 whole-number tracts** — a 6-digit tract code ending in `00` (`007100`) is sent as the 4-digit form that vintage lists (`0071`) at the tract level, in `tract_fips`, in a GEOID, and in a `census_compare_geographies` `geographies` entry, and the notice says so. The `tract_fips` pattern error tells a caller to send a 4-digit 2000 tract as its 6-digit form, and the `geography_fips` GEOID description names the short width on dec/pl 2000. ([#97](https://github.com/cyanheads/census-mcp-server/issues/97))
- **Full GEOIDs in `census_query_data` `geography_fips`** (`53053`, `29213480108`) are read as their parent codes plus the level code, and the parents are taken from the GEOID when `parent_fips`, `county_fips`, and `tract_fips` are omitted. The `no_data` hint and unmatched-code notice add the GEOID form to the width guidance. ([#100](https://github.com/cyanheads/census-mcp-server/issues/100))
- **`no_data` hint on `cbp`, `ecnbasic`, and `nonemp`** no longer blames all-category defaults such as `EMPSZES` and `LFO`; a two-digit NAICS `31`, `32`, `33`, `44`, `45`, `48`, or `49` names its published range (`48` → `48-49`). ([#101](https://github.com/cyanheads/census-mcp-server/issues/101))
- **`geography_level`** is trimmed and lowercased before use, so `"County"` or `" block group "` gets the same answer and hints as the lowercase name.
- **`census_compare_geographies`** — the notice for a bare code that matched more than one geography names the level and offers only the scope inputs the comparison left open (`within`, `within_county`, or neither), instead of always saying "more than one state" and pointing to `within`.
